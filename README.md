# Medical AI Evaluation Lab

An experimental portfolio project for structured and reproducible evaluation of medical AI responses.

The project focuses on evaluating medical AI beyond simple factual accuracy by preserving clinically important safety failures separately from aggregate scores.

---

## Project Goal

The goal of this project is to build a practical Medical AI Evaluation workflow that can:

- Define an evaluation scope
- Apply a structured medical AI rubric
- Run synthetic medical test cases
- Evaluate real outputs from a medical language model
- Preserve critical safety failures separately from aggregate scores
- Record failure labels and evaluator notes
- Export reproducible JSON evaluation results

This project is designed as a portfolio and research experiment.

It is not a clinical validation study.

## Day 2 — Evaluation Rubric

Created:

`rubric/evaluation_rubric_v1.md`

The rubric evaluates eight default dimensions:

1. Medical and factual correctness
2. Clinical safety
3. Task completion
4. Relevance and focus
5. Uncertainty handling
6. Evidence support
7. Communication quality
8. Internal consistency

Each dimension is scored from 0 to 4.

The framework also supports failure labels and a separate safety flag.

A high aggregate score does not cancel a clinically important safety failure.

## Day 4 Test Set

Ten synthetic patient-facing cases were evaluated.

The cases tested:

- Patient education
- Emergency escalation
- Diagnostic uncertainty
- Scope control
- Clinical safety
- Communication quality
- Medical correctness
- Handling of incomplete information

Examples included:

- Postpartum severe headache with blurred vision and severe hypertension
- Progressive breathing difficulty with lip swelling and widespread hives
- Confusion and heavy sweating in a patient with diabetes
- Sudden facial droop and difficulty speaking
- Diagnostic uncertainty from nonspecific symptoms
- Limitations of a normal chest X-ray

---

## Day 4 Evaluation Method

MedGemma generated the model responses.

The model did not score its own outputs.

The responses were reviewed against `Evaluation Rubric v1`, and the resulting dimension scores, failure labels, evaluator notes, and evidence notes were passed through the evaluation pipeline.

This separation is intentional:

```text
Model generation
      |
      v
Raw model output
      |
      v
Independent rubric-based review
      |
      v
Evaluation pipeline
```

## Day 4 Results

The experimental run produced:

- 10 model-generated responses
- 10 structured evaluations
- Mean normalized score: 83.44%
- 2 cases with a safety flag
- Multiple detected failure types

Observed failure labels included:

- Overconfidence
- Poor uncertainty handling
- Unsafe recommendation
- Missed red flag
- Factual error
- Incomplete answer
- Communication problem
- Unsupported claim
- Scope violation

Two cases were safety-flagged in this run:

- `day4_004`
- `day4_006`

The aggregate score alone therefore did not determine whether a response was considered safe.

---

## System-Level Finding

Several responses were truncated because the generation run used:

`max_new_tokens = 300`

This matters because an evaluation result can be affected by both:

- Model behavior
- System configuration

For example, an otherwise useful response may receive an `incomplete_answer` label because generation stopped before the response was finished.

This is an important distinction for future system-level evaluation.

# Configure the MedGemma Endpoint

The MedGemma generation step requires a running remote endpoint.

The endpoint should be supplied through an environment variable rather than permanently hardcoded into the repository.

Example in PowerShell:

```powershell
$env:MEDGEMMA_ENDPOINT="https://your-current-gradio-url.gradio.live"
```

The temporary endpoint will stop working when the remote Colab session or Gradio share URL expires.

# Evaluation Philosophy

A fluent medical response is not automatically a safe response.

This project separates:

- Aggregate quality
- Clinical safety
- Failure type
- Evaluator reasoning
- Model behavior
- System configuration

A response can therefore receive a relatively high aggregate score while still containing a clinically important failure.

---

# Important Limitations

This project is experimental.

It is not intended for:

- Direct clinical use
- Diagnosis
- Treatment decisions
- Patient management
- Clinical validation
- Regulatory validation
- Medical-device certification

The current test set contains only synthetic cases.

The Day 4 run contains only ten cases and should not be interpreted as a general performance estimate for MedGemma.

The scores reflect a rubric-based review of this specific experimental run.

Model outputs require independent clinical review.
